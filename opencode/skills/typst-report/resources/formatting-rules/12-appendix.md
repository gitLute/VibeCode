# Приложения

Блок: приложения к отчёту через единый блок `#appendix` из `styles.extended`
пакета Ghost.

## Синтаксис

```typ
// Перед каждым приложением — явный разрыв страницы
#pagebreak()

// ПРИЛОЖЕНИЕ А
#appendix(letter: "А", title: "Текст программы", kind: "обязательное")

\   // пробельная строка обязательна

Код файла ./sort.py

\   // пробельная строка между описанием и кодом

```python
def quicksort(arr):
    ...
```
```

## Правила

1. **Принудительный разрыв страницы перед приложением** ставится явным
   `#pagebreak()`.
2. Один вызов `#appendix` объединяет **невидимый заголовок первого уровня**
   (маркер приложения для содержания) и **видимую шапку** приложения
   («ПРИЛОЖЕНИЕ А / (вид) / Текст программы»).
3. Параметры: `letter` — буква приложения, `title` — название, `kind` — вид
   приложения.
4. **Виды приложений** (`kind`): `"обязательное"`, `"справочное"`, `"рекомендуемое"`.
5. **После `#appendix` пробельная строка обязательна**; между описанием и кодом —
   тоже пробельная строка.
6. В приложение могут включаться: математические расчеты и формулы, таблицы
   с большим количеством данных, схемы алгоритмов, исходные тексты программ,
   результаты промежуточных вычислений и т. п.

### Обозначение приложений

7. Приложения обозначают **заглавными буквами русского алфавита, начиная с А**,
   за исключением букв **Е, З, Й, О, Ч, Ъ, Ы, Ь**.
8. Если в отчёте **одно приложение**, оно также обозначается «ПРИЛОЖЕНИЕ А».

### Нумерация внутри приложений

9. Таблицы и рисунки в приложении нумеруются по букве приложения
   **автоматически**: `#appendix` публикует букву в `state("appendix")`,
   и блоки сами формируют подпись:
   - `#table-block(...)` в приложении Б → «Таблица Б.1»;
   - `#picture(...)` в приложении Б → «Рисунок Б.1».
   Параметр `part` передавать не нужно; он остаётся только как явное
   переопределение.
10. В приложениях так же работают `#raw("...")` и `#raw(read("..."))` для
    листингов.

## Внутреннее устройство #appendix (из extended.typ)

- **Сброс счётчиков**: при вызове `#appendix` сбрасываются счётчики рисунков и таблиц
  данного приложения — `counter("fig-" + letter).update(0)` и
  `counter("tab-" + letter).update(0)`. Отсюда нумерация «Рисунок А.1», «Таблица Б.1».
- **Публикация буквы**: `#appendix` пишет текущую букву в `state("appendix")`.
  Блоки `#picture` и `#table-block` читают её и нумеруют свои объекты по букве
  приложения автоматически — ручной `part` в приложении не нужен.
- **Невидимый заголовок** (маркер для содержания) подавляется локальным
  `show heading: none` — а НЕ `#hide(...)`. Заголовок остаётся в дереве документа
  и попадает в содержание, но в макете места не занимает: страница приложения
  начинается с той же верхней границы, что и остальные (через `#hide` после
  `#pagebreak()` сверху оставалась бы пустая строка).
- Название маркера — **ЕДИНЫЙ text-элемент без переносов строк внутри литерала**:
  `heading(level: 1, numbering: none)[#text("ПРИЛОЖЕНИЕ " + letter + " " + title)]`.
  Если разбить название на несколько элементов, `has("text")` в записях содержания
  вернёт `false`, `fix-case` не применится, и в содержание попадёт ПРОПИСНАЯ шапка
  («ПРИЛОЖЕНИЕ А …»), а не «Приложение А …».
- **Видимая шапка** по центру: «ПРИЛОЖЕНИЕ А / (обязательное) / Текст программы».
- Автоматический разрыв страницы в стиле НЕ предусмотрен — только явный
  `#pagebreak()` в отчёте.

## Запреты

- Не начинать приложение без `#pagebreak()`.
- Не пропускать пробельные строки после `#appendix` и вокруг содержимого.
- Не использовать в `letter` запрещённые буквы (Е, З, Й, О, Ч, Ъ, Ы, Ь).
- Не передавать `part` у таблиц и рисунков в приложении: буква определяется
  автоматически (явный `part` — только как осознанное переопределение).
