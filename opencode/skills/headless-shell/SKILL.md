# Неинтерактивная среда

Среда headless: нет TTY/PTY. Команда, ожидающая ввода, запускающая редактор или
пейджер, зависнет и упадёт по таймауту. Работай как в headless CI.

## Порядок предпочтения

Прежде чем запускать спорную команду, подбери решение по этой очерёдности:

1. **Неинтерактивный флаг.** Ищи в `references/cheatsheet.md` по своему инструменту.
2. **`< /dev/null`.** Закрывает stdin, обезвреживает большинство промптов.
3. **heredoc или `yes |`.** Когда скрипту нужны ответы на вопросы.
4. **`timeout`.** Последний рубеж. Ставь его на всё спорное и на любой скрипт.

```bash
timeout 30 cmd < /dev/null                 # закрытый stdin плюс страховка
timeout 60 yes | ./install.sh || echo "Ошибка"
timeout 60 ./configure.sh <<'EOF' || echo "Ошибка"
--prefix=/usr/local
EOF
timeout 30 ./script.sh || echo "Ошибка"    # последний рубеж
```

Проверяй код возврата (`cmd || echo "Ошибка: $?"`), иначе провалившийся шаг
выглядит как успешный.

## Жёсткий запрет

Никогда не вызывай, ни в какой форме:

- **Права root**: `sudo`, `sudo -S`, `su`, `pkexec`, `doas`. Пароля у модели нет,
  а передача пароля через `-S` или пайп — утечка секрета в логи и `ps`.
  Обход через `docker --privileged --user root` и `systemd-run` запрещён тоже.
  Нужны права — остановись, приведи точную команду и попроси пользователя выполнить её сам.
- **Редакторы**: `vim`, `vi`, `nano`, `emacs`, `pico`, `ed`, `visudo -e`, `crontab -e`.
- **Интерактивные оболочки**: `bash -i`, `zsh -i`.
- **ПИН-коды и ввод с клавиатуры**: `gpg --edit-key`, `pass`, `pinentry`,
  `ssh-keygen` без `-N ""`.

## Не меняй семантику команды

В колонке «хорошо» справочника стоит неинтерактивный эквивалент **той же**
операции. Флаги `--ff-only`, `--force`, `--no-verify` меняют результат работы,
а не только способ ввода. Используй их, только когда пользователь явно попросил
именно это.

## Справочники

Читай по необходимости, а не весь подряд:

| Файл | Когда читать |
|---|---|
| `references/cheatsheet.md` | Нужен неинтерактивный вариант конкретной команды: пакетные менеджеры, git, файлы и система, ssh, docker, gh |
| `references/hazards.md` | Команда может зависнуть или уйти в диалог: полный каталог промптов, которых нет в справочнике, и причина зависания каждого |
| `references/env.md` | Переменные окружения, отключающие промпты, и готовые строки для их подстановки |

## Полезные приёмы

- Ищи неинтерактивные опции: `cmd --help 2>&1 | grep -i "force\|yes\|non-interactive"`.
  Без `2>&1` подсказка из stderr теряется, а флаги часто именно там.
- Изучай флаги через web-поиск, если `--help` не даёт ответа.
- Длинный вывод сохраняй в файл и читай выборочно:
  `cmd > tmp/out.log 2>&1; tail -n 50 tmp/out.log`
- У инструмента shell есть параметр `timeout` — выставляй его явно, а не полагайся
  на значение по умолчанию.
