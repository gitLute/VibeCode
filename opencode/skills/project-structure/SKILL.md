# Структура проекта

## Ожидаемая структура

```text
ProjectRoot/
├── src/                        # исходный код программы
├── out/                        # скомпилированные файлы
├── img/                        # скриншоты, схемы, изображения и т.д.
├── typst/                      # файлы отчёта (.typ), если такие требуются; только для файлов отчёта, не изображений
│   └── report.typ
├── tmp/                        # временные файлы, вывод результатов запуска и т.д.
├── report.pdf                  # готовый отчёт (скомпилированный из .typ), если требуется
└── README.md                   # описание проекта
```

Создать каркас одной командой:

```bash
bash ~/.config/opencode/skills/project-structure/templates/scaffold.sh .
```

Скрипт создаёт только недостающие каталоги и пустой `README.md`, ничего не
перезаписывает.

## Условия

- Создай ожидаемую структуру, если работаешь в пустом проекте.
- Если в проекте уже есть `README.md` / `readme.md` — пиши в него, а не создавай новый.
- Не переименовывай и не удаляй уже существующие каталоги и файлы без явного запроса пользователя.
- Каталог сборки выбирай по экосистеме языка: `out/` для JVM, `build/` для C/C++, `dist/` для JS, `target/` для Rust. `out/` — значение по умолчанию, если для языка нет устоявшегося соглашения.
- Заведи `.gitignore` и добавь в него каталоги сборки и временные файлы (`out/`, `tmp/`, а также фактические артефакты сборки этого проекта). Готовые результаты вроде `report.pdf` в `.gitignore` не добавляй.

## Требования к README.md

`README.md` — это инструкция к проекту. Должен содержать:
- краткое описание алгоритма программы;
- объяснения основных участков кода;
- инструкцию по сборке/компиляции проекта (если применимо; для интерпретируемых языков — по установке зависимостей);
- инструкцию по запуску проекта;
- инструкцию по использованию проекта, примеры использования.

Заполняй README по мере работы, а не в конце: он должен соответствовать коду,
который уже компилируется.

## Отчёты (Typst)

Создание и сборка отчёта выполняется только по скиллу `typst-report`.
Эталоны и шаблоны лежат в `~/.config/opencode/skills/typst-report/resources/`.

1. создай файл отчёта `typst/report.typ` по эталону из скилла;
2. скомпилируй его в `report.pdf` (команда компиляции указана в скилле);
3. исправляй ошибки компиляции до чистой сборки.

Если `img/` недоступен для чтения, изображения для отчёта бери из внешних
источников и описывай их текстом в `.typ`, не рассчитывая на визуальную проверку.
